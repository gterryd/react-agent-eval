# 私人笔记问答 Agent（ReAct + 工具调用 + 评测体系）

一个以 **Agent 为中心**的问答系统：检索只是它的一个工具，不是全部。
它自己决定要不要查、查什么、查几次、要不要算，答不出来会说"没有"而不是编。

> **关于定位**：这不是一个"能上线的产品"，是一个**评测导向的工程练习项目**。
> 它真正的产出不是 93.3% 这个数字，而是**一套能证明数字可信的方法**，
> 以及下面那份[踩坑账](#六我犯过的错15-次)。

## 一、它能做什么（一次真实提问）

问：**"干净数据那次训练，平均每步要多少秒"**

它走了 3 步，中间两次调工具：

| 步 | 它在想 | 它做了什么 | 得到 |
|---|---|---|---|
| 1 | 要先查那次实验的记录 | `read_experiment("干净数据全量")` | `训练秒数: 24987, 步数: 450` |
| 2 | 拿到秒数和步数了，该算了 | `calculate("24987/450")` | `55.53` |
| 3 | 可以回答了 | 不调工具 → 输出答案 | "平均每步约 **55.5 秒**" |

**第 2 步调什么，是第 1 步的结果决定的** —— 它事先不知道有"训练秒数"这个字段。
这就是 Agent 和 RAG 的分界线。

## 二、为什么是 Agent 不是 RAG

| | RAG | 这个项目 |
|---|---|---|
| 查不查 | 固定查一次 | 自己决定（拒答题实测 **0 次**工具调用）|
| 查几次 | 1 次 | 1-3 次，必要时并行 |
| 能不能算 | 不能 | 能（`calculate`，安全 AST 求值）|
| 后一步依赖前一步 | 不支持 | 支持（上面那个例子）|

**最初想做 Agent 的真实理由**（不是"因为更先进"）：
我问自己"42 辆车误检那次用的是脏数据还是干净数据"，**我自己答错了**。
连我本人都会记混自己做过的实验 —— 所以需要的不是一个会聊天的东西，
是一个**每句话都能查证**的东西。

## 三、架构

```
demo.py (Gradio 界面)     api.py (FastAPI 5 接口)
            └──────────┬──────────┘
                       ↓
     agent.py  ←→  graph_agent.py     ← 两套编排，行为已验证一致
     (手写 while)    (LangGraph 状态图)
                       ↓
                   tools.py           ← 5 个工具 + Tool Schema
                       ↓
              kb.py (切片)  vec.py (BGE 向量检索)
```

**5 个工具**：`search_docs`（向量检索）/ `read_config` / `read_experiment` /
`calculate` / `list_files`

**两套编排并存，一行都没删**。图结构：

```
__start__ → [think] ──条件边──→ [act] ──回边──→ [think] → __end__
```

手写版里"还要不要继续"是循环中间一句 `if not msg.tool_calls: break`，
藏着看不见；图版本逼它变成一个有名字的函数 `should_continue` —— **能画、能指、能讲**。

两版实测对照（4 种路径，28 项断言全过）：

| 题型 | 手写步数 | 图步数 | 手写token | 图token | 工具选择 |
|---|---|---|---|---|---|
| 单工具 | 2 | 2 | 1693 | 1693 | 一致 |
| 多步 | 2 | 2 | 2013 | 2035 | 一致 |
| 检索 | 2 | 2 | 4526 | 4531 | 一致 |
| 应拒答 | 1 | 1 | 847 | 844 | 一致（都没调）|

> 耗时列故意不放：同进程里先跑的那版替后者背了向量模型冷启动（17.5s vs 2.9s），
> **那个差值是假的**。能比的是 token —— 几乎相同，说明两版喂给模型的是同一份东西。

## 四、评测体系（这个项目的重点）

**35 道题 × 3 次 = 105 次运行**，9 类：检索/配置/多步/计算/拒答 + 4 类难题（部分可答/
模糊/三工具/陷阱）。跑 3 次是因为**实测发现同一份代码同一道题两次行为不同**，
`temperature=0` 也压不住 —— **单次结果不能当结论**。

| 指标 | 结果 |
|---|---|
| 任务完成率 | **93.3%** |
| 工具选择准确率 | **93.3%** |
| P95 延迟 | **3.40s** |

### 失败归因（7 次失败逐条归类）

| 归因 | 次数 | 占比 |
|---|---|---|
| **① 规划错**（该查却不查）| **7** | **100%** |
| ② 工具选错 | 0 | 0% |
| ③ 参数错 | 0 | 0% |
| **④ 检索没召回** | **0** | **0%** |
| ⑤ 汇总错 | 0 | 0% |

**④ 是 0 这件事是被证明的，不是假设的。** 最典型的一题，它答"知识库里没有
按类别拆分的准确率数据" —— 我写了诊断脚本逐层验证：

| 环节 | 实测 |
|---|---|
| 知识库有数据吗 | 有，2 个片段含那两个数字 |
| 向量检索召回得到吗 | 召回了，排**第 2 名**，相似度 0.549 |
| `search_docs` 返回对吗 | 返回 3813 字，**两个数字都在里面** |
| 它调了 `search_docs` 吗 | ❌ **没调。工具列表是空的** |

**它编造了"没有答案"** —— 这比编造答案更隐蔽，因为听起来很诚实。
结论：瓶颈在**规划层**，不在检索层。该修的是提示词和工具描述，不是换 embedding 模型。

## 五、工程部分

### 可观测：全链路追踪
每次运行落两份盘 —— `logs/<run_id>.json`（单次完整决策链，排查用）、
`logs/index.jsonl`（一行一次摘要，统计用，不必读几百个大文件）。
记的东西包括**每步的思考文字**（ReAct 的 Reason，不只是 Act）、每次 API 调用的
耗时和 token、工具参数和返回。

**耗时拆成"等模型"和"跑工具"两类**。理由：知道"这次花了 3 秒"没用，
得知道花在哪 —— 等模型久是 API 延迟（我优化不了），跑工具久才该优化检索。
实测结论：**99.6% 在等 API，检索占 0.4%**。

### 错误处理与降级
- 指数退避重试 1s → 2s，**带随机抖动**（所有客户端严格等 1s 会同时重试撞一起）
- **区分该重试和不该重试**：超时/429/5xx 值得等；**key 错、参数非法重试一万次还是错**，
  立刻抛。这是这块的重点
- 重试完仍失败 → 不抛异常，回一句人话 + 日志标 `degraded`
- 重试 3 次只 sleep 2 次（最后一次失败后再等是纯浪费）
- 验收分两轮：**21 项注入故障测逻辑**（假 client + 假时钟，不真等 7 秒）
  + **真实 API 回归**证明核心循环没被改坏

### 服务化
FastAPI 5 个接口：`POST /chat`、`GET /tools`、`GET /health`、
`GET /runs`、`GET /runs/{run_id}`。
后两个把日志开成了接口 —— **日志能查才叫可观测**，躺在硬盘上那叫存档。
输入校验用 pydantic：`question` 限 1-500 字，`max_steps` 夹在 1-8
（`max_steps=999` 放过去 = 一次请求转 999 圈、每圈调一次大模型 = 烧钱）。

### 安全
- `calculate` **没用 `eval`**（`eval` 能执行任意代码，模型传什么就跑什么，是真实漏洞）
  → 改用 `ast` 白名单，只放行数字和四则运算
- `GET /runs/{run_id}` 校验 id 格式，防路径穿越读走 `.env`

## 六、我犯过的错（15 次）

**这一节是我认为这个项目最有价值的部分。** 别人能复制代码，复制不了这些。
分三类，性质完全不同。

### 第一类：我的判定标准错了 —— 11 次

两轮共 32 次失败，**23 次是我的卷子有问题，不是 Agent 的问题**：

| 我错在哪 | Agent 实际做的 |
|---|---|
| 逼它必须调工具才算过 | 读工具说明书就知道查不到，**直接拒答是更优解** |
| 要整数 41/90/49 | 答 41.7/90.35/48.65，**数值全对只是带小数** |
| 要含约数"30" | 答 29.45，**比我的标准更准** |
| 要它猜"那次实验"指哪次 | 列出三次全表 + 反问澄清 |
| 要它答出某个具体数 | 拒答：工具确实查不到那个指标 |

第二轮那 5 道病根完全相同：**我在惩罚"反问澄清"和"诚实拒答"这两个正确行为。**
→ 改用 `must_any`（任一命中即可，判"行为"而不是卡措辞），
以及 `must_not` + 否定语境保护（它说"不是 16.6"不该被当成附和 16.6）。

最后两次是同一天连着犯的，更值得记：
1. 断言写 `"来源" in 答案`，代码实际拼的是**"出处"** → FAIL 了，但功能一直是好的
2. 改成查 `"出处" not in 纯答案` → **PASS 了，但那是撞运气**：模型自己在正文里
   写的是"（来源：xxx.md）"，措辞不同所以躲过了检查

**最终改法：不猜措辞，验结构** —— `完整版.startswith(纯答案)` 证明出处是纯追加、
没改动原文。**这条升级成了一条规矩。**

### 第二类：我下错结论 —— 3 次（同一个模式：没看明细就下结论）

| 我的错结论 | 真相 | 靠什么查出来的 |
|---|---|---|
| "它答不出，可能检索没召回" | **瓶颈在规划层，检索零失败** | 诊断脚本逐层验证 |
| "63% 时间花在检索上" | **99.6% 在等 API，检索占 0.4%**。那 15 秒是首次加载向量模型的一次性开销 | 核对单次明细（15.18s / 0.0s / 0.016s）|
| "路径穿越测试 PASS，我的校验有效" | **404 是路由层返的，我的校验一次都没执行** | 核对访问日志 + 补一个能走进 handler 的用例 |

**这三个若不核对，就会错误地宣称"我优化了检索"、"我做了穿越防护且测试通过"
—— 一追问"404 是谁返的"当场穿。**
第三次最隐蔽：**测试是绿的，绿灯本身给了虚假的安全感。**

### 第三类：假造结果 —— 1 次（最严重）

实验脚本里把结果写死了：`print(CONFIG.get('rank'))`。
于是参数填错成 `training.rank`（实际查不到）时，**屏幕照样显示"能查到 16"**。

因此建立的三个机制（这才是这条的价值）：
1. **所有结论必须程序当场算**，不许预先写死；有 FAIL 则退出码非 0 响亮失败
2. **改了尺子先量一次已知长度的东西** —— 13 条用例全用实测过的真实回答，
   且**该判失败的也必须挂**（防为了分数好看把标准放水成谁都能过）
3. 硬规则：**随时可以要求我指出"这个结论是哪行代码算的"，指不出来就是在编**

## 七、已知局限（不装没有）

1. **出处只能覆盖"检索来的那部分"，不能保证整个答案都有依据。**
   实测过一次：问"fp16 在哪里用了"，检索返回的是排查过程，
   但答案里"不用 fp32：显存翻倍，3B 约 12G"这类内容**笔记里没有，是模型自身知识**。
   → 含义：它会把检索内容和模型知识混着输出，而溯源只盖住了前者。
   没修，两条可选路：系统提示里要求区分"笔记里写的"vs"我补充的"；或者保留并主动说明。

2. **服务没有鉴权、没有限流**，只绑 `127.0.0.1` 供本机演示。
   真要对外至少还要：API Key/JWT、按 IP 限流、请求体大小上限、CORS 白名单、密钥托管。
   没做的理由：单用户的评测导向项目，没有真实流量。

3. **单轮对话**，不支持追问（"那它呢？"这种指代解析没做）。

4. **93.3% 是在我自己出的 35 道题上测的**，题目分布由我决定，不是公开基准。
   换一批题数字会变。

5. **只在一个模型（DeepSeek）上测过**，没做跨模型对比。

6. 检索相似度实测多在 0.44-0.48 区间（阈值 0.35），**相关性其实偏弱**。
   答案质量有一部分来自原始笔记本身写得完整，不全是检索准。

## 八、怎么跑起来

```bash
pip install -r requirements.txt
cp .env.example .env     # 然后填入你的 DEEPSEEK_API_KEY
```

> ⚠️ **知识库未入库**：它是我的私人学习笔记。
> 想跑起来，把你自己的 markdown 笔记放一个目录，在 `.env` 里设 `KB_ROOT` 和 `KB_FILES`。
> 没设的话程序会**明确报错告诉你怎么配**，而不是静悄悄返回空结果。

```bash
python demo.py                                    # Gradio 界面 → 127.0.0.1:7860
python -m uvicorn api:app --host 127.0.0.1        # FastAPI → 127.0.0.1:8000/docs
python 测重试.py                                   # 重试与降级验收（不花钱、不联网）
python 对照_手写vs图.py                            # 两套编排对照（会调 API）
python step5_跑基线.py                             # 跑完整基线 105 次（★会花钱）
```
